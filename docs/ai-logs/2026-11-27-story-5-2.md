## 3. Build

The AI built it directly from the spec:
- `services/holdup.py` (new): reads the two stored rows and turns them into the cards' words and numbers.
- `services/watchlist.py`: the Scan header moved into one function that both Scan pages call, with the list of tabs. A Scan gets the Hold-up tab only when it has a stored Hold-up result.
- `web/`: the route `/scans/<id>/hold-up`, one shared template for the header and tabs, the new page, and CSS for the cards and for two new pill styles. No JavaScript was added.
- `README.md`: the result table, five limits, and a tidier stage 2 list.

**One deviation from the spec's file list:** the spec planned a yes/no flag on the header saying whether the Scan has a Hold-up result. The AI made it a list of tabs instead, so the template needs no extra value to mark the current tab and Epic 6 can add the Copy Test tab in one place.

**What the page shows for a full offline Scan** (a new Scan run through the real app, 53 seconds):

| Group | Verdict | Odds with no edge | Bets counted | Real PnL | Wallets | Dropped |
|---|---|---|---|---|---|---|
| Before-Cut-off Passers | *Skilled (high confidence)* | fewer than 1 time in 10,000 | 300 | $6,000 | 10 | 7 |
| Comparison Group | *No evidence of skill* | more than half the time | 409 | −$19,217 | 999 | 996 |

The page, the stored rows and the README agree. A Scan from before Story 5.1 has one tab only, and its Hold-up address gives *Page not found*.

**Edvard's test.** `test_fr17_no_real_wallet_is_a_passer_in_the_offline_scan` runs a real offline Scan of the committed Sample Wallets and checks two things: no real Wallet is a Passer by the app's own rule, and the Passers that are tested are exactly the three made-up Wallets built to keep winning. The AI then planted a bug to see it fail (a rule that also lets *Likely skilled* pass): the test failed and named the real Wallet that would have become a Passer, 0xcf0d7f.

## 5. Review

Three helpers reviewed the diff without seeing this chat. They filed 30 findings. None found a wrong number on the page.

**Fixed (22), the ones that mattered most:**
- **The README's group sizes were not really tested.** The numbers 10, 7, 999 and 996 were typed into the same test that checked them, and every Scan in the tests used 40 coin-flippers, not 1,000. Now the six coin-flippers that pass by luck are listed, a test proves the list against the generator (all 1,000 on the Linux CI job), and the sizes are built from that list.
- **Very large amounts did not fit.** With the AI's first CSS, an amount like −$123,456,789 made the page scroll sideways at 320 px. The AI planted the old CSS back to confirm it. The figures now go to one column wherever two would be too narrow, tested at nine widths.
- **Edvard's sentence was only proven for Seed 44.** The Seed is a setting. A test now checks every real Wallet again under four other Seeds: none passes.
- **The offline box could give the wrong reason.** If the Passers were the group dropped more, the box would still blame the coin-flippers in the Comparison Group. That cannot happen on the Sample Dataset, but the code allowed it. Now it stays silent in that case.
- **Two tests could not fail.** One checked that an amount stays on one line with a check that is true for any element; one claimed more than it guarded. Both were rewritten, and planted bugs now fail them.
- Smaller ones: an outline for the Verdict pills in Windows High Contrast, three loose README sentences, a rule written twice in the Watchlist code, and a memlog entry that tagged the AI's design choices as Edvard's decision (corrected with a new entry).

**Rejected (7)**, for example: the sentence for a Scan with no Passers names the Copy Test, which is not built yet (those are the plan's own words); and test files importing helpers from each other (the repository's habit since Story 4.5).

**Deferred (1):** `docs/accessibility-check.md` covers stage 1 only and names none of the Scan pages, though their checks exist as browser tests. It is in the deferred-work list.

**For Edvard (1):** a reviewer missed a line on each card saying who is in the group. The plan had no such line, so the AI did not add it and asked him instead (see section 6).

After the fixes the AI planted 11 more bugs against them. 9 were caught at once; 2 were not (three columns allowed in a wide card; an amount allowed to wrap), and each got an assertion and was then caught.

**Two choices the AI made inside Edvard's decision on the info box**, shown to him in the review summary: each of the box's two sentences is left out when it would describe nothing (the first when no Passer is tested, the second when the warning is there because the Passers were dropped more).
