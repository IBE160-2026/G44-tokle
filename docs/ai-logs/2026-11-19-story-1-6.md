## 3. Bugs found in the AI's code

The AI's own first test run caught one mistake: its new rule "only the mode switch reads the Offline setting" also flagged `settings.py`, which builds that setting. The rule now allows it.

The three reviewers raised 43 findings, grouped into 23. The AI checked each against the code:

| Found by | Bug | Fix |
|---|---|---|
| All three reviewers | `load-sample` crashed with a raw error (a traceback) when `offline.db` was broken or locked. A reviewer showed it with a text file named `offline.db` | It now stops with a plain message; test with a broken database |
| Verification and edge-case reviewers | A Sample file's address was checked only for capital letters; spaces or a wrong length got through and later crashed `load-sample` | The address must be `0x` plus 40 lower-case hex characters; 5 bad addresses tested |
| Blind and edge-case reviewers | Each thread got a database connection that was never closed. The web server in Story 1.7 starts a thread per page request, so connections would pile up | A new connection closes those of finished threads; tested |
| Blind and edge-case reviewers | If saving failed at the very last step (COMMIT), the connection stayed stuck and every later write on it failed | The failed save is rolled back; tested by forcing a failure at that step |
| Verification reviewer | The test for "writers wait for each other" passed 48 times out of 50 even with the safety removed | Two exact tests: another writer is shut out from the start, and a waiting write succeeds once the lock is freed |

When writing the test for the connection fix, the AI first expected 1 connection left; the run showed 2. The code was right (clean-up happens when the next connection opens), so the test was corrected to check that it stays at 2 instead of growing to 6.

In total: 7 fixed, 16 rejected with reasons (for example, "two fetches of the same Wallet at once can't happen in Epic 1, since `load-sample` is the only thing that fetches and it runs on one thread; Story 2.2 adds the planned lock"), 0 deferred. The full table is in the spec's Review Triage Log.
