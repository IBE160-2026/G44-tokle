## 2. Planning

The AI read the plan and the code itself, with no helper. It asked six questions, each with a recommendation:

1. **The honesty-notes line for a Scan's result.** The plan says such a result must say it rests on two windows (the bets before and after the Cut-off Date) but gives no words. The AI proposed wording, shown always. **Edvard agreed** (AI rec).
2. **What counts as "Wallets tested" in the luck sentence.**
   - (a) Every Wallet in the Scan, including those with *Not enough data*.
   - (b) Only Wallets that got a Verdict.

   The AI recommended (a), because it matched the PRD's own example ("2 of 200"). **Edvard changed it to (b)**: "the luck number should only count wallets that actually got tested". A Wallet with too few bets cannot pass, so counting it would make the floor too high.
3. **Shortlist size and "not fully read" count.** The architecture and PRD say the Scan page shows them; the story text forgot them. **Edvard chose one extra header line** (AI rec) over removing them from the plan.
4. **How to name a Market that could not be read in full.** The database stores no Market titles. **Edvard chose a short ID, volume and end date** (AI rec) over a database change to store the title.
5. **Spec size** (about 2,400 tokens against the 1,600 guideline). **Edvard kept it whole** (AI rec).
6. **Helpers.** **Edvard chose helpers for the review only** (AI rec), as in 4.3 and 4.4.

His answer to question 2 raised one more question. With (b), a Scan of 200 where 13 Wallets have too few bets would say "Scan of 200 Wallets" and then "1.9 of 187". The AI suggested adding "with a Verdict" to the sentence, so the number explains itself ("At least about 1.9 of the 187 Wallets with a Verdict would pass by luck alone…"). **Edvard agreed** (AI rec).

He said "approve and continue". The decisions went into the PRD (FR-11, FR-16, Glossary and its decision log), the architecture (AD-8, AD-21), epics.md, EXPERIENCE.md, DESIGN.md, the Epic 4 summary and the three memlogs before any code was written.

## 3. Build

The AI built it directly from the spec. The new parts:
- `services/watchlist.py`: the Watchlist page and the Verdict opened from it.
- `watchlist.html` and a small script, `tag-tip.js`, so Esc hides the tag's explanation.
- In `services/scan.py`, the code that puts a Wallet's two parts together became its own function, so the Verdict page tests exactly what the Scan tested.

**Problems found while building:**
- **The browser tests** showed that the AI's narrow-screen rule never applied (it sat above the rule it was meant to override). The summary card stayed beside the title, and the page scrolled 24 px sideways at 320 px.
- **Screenshots** showed three more problems:
  - The disclosure copied the chart's right-hand style.
  - The table caption was cut off on a phone.
  - The tooltip was clipped by the table's scroll box.
- **The full test run** showed that after Esc, Tabbing back to the tag sometimes left the explanation hidden. The script used a timer that raced the focus move in Chrome. It now re-shows when focus or the pointer comes back to the tag.
- **The project's own guard tests** caught three slips:
  - An odds phrase written in a code comment.
  - Hover styles without a matching keyboard-focus style.
  - Test descriptions without a plan reference.

## 4. Review

**Pass 1.** Three reviewer helpers filed 27 findings. The AI checked each against the code. Two were questions only Edvard could answer, so the workflow sent the story back to planning: the AI put the code back to the start and kept a copy to rebuild from. It asked:

The AI then rebuilt with A to C and 9 smaller fixes from the review:

**Pass 2.** Three new reviewers filed 26 findings: 8 fixed, the rest rejected or repeats of pass 1, none deferred. The most useful one: the test that a Watchlist row and its Verdict page agree only ever compared Wallets with *Not enough data*, so it never checked a p-value. A new test uses a Skilled Wallet under a different Seed, and fails if the page uses the wrong Seed. Also fixed:

**Rejected, for example:** "0.0 of the 3 Wallets" for Scans with 1 to 4 Wallets with a Verdict (it follows the plan's rounding rule, and new wording would be Edvard's call), and checking at run time that a Verdict still matches its stored row (only a later change to the calculation could break it). **Checks that the new tests work:** the AI planted six bugs on purpose, one per new rule, and ran the tests each time. A test with two different times was added, and then all six were caught. The wrong-Seed bug from pass 2 is caught too.

## 5. After the review: small numbers

When Edvard read the summary, the AI pointed out the rejected "0.0 of the 3 Wallets" case. **Edvard asked for the small numbers to read the way a person would say them**, then OK'd the commit. He set the goal; the AI chose the wording and wrote it into the plan first (EXPERIENCE.md, epics.md, the PRD check, the Epic 4 summary, the UX memlog):
- From 100 Wallets with a Verdict, the number is whole: "At least about 2 of the 150 Wallets with a Verdict would pass by luck alone, …" (it was "1.5").
- Below 100, a number under 1 makes no sense, so the sentence gives the rate and what it means: "About 1 in 100 Wallets would pass by luck alone, probably more, because these Wallets were picked for high profit. With only 37 Wallets with a Verdict, even one passing could be luck."
