## 4. Review

Three reviewer helpers filed 31 findings. The AI checked each against the code: 16 fixed, 15 rejected with a reason, none deferred. All are in the spec's triage log.

**Fixed, for example:**
- **A crash in AI-written code**: a Cut-off Date long before 1970, such as 1 Jan 1960, was accepted. On Windows the Scans page then broke on every load, because Python's time conversion refuses such old times there. The AI reproduced it on this PC first. Stored dates are now turned back into dates in one place (`window.cutoff_day`), with a test reaching back to the year 1.
- **Another website could still start a Scan** with a trick called DNS rebinding: a site makes its own name point at this computer, so its requests pass the "same site" check. POSTs now also have to address the app as `127.0.0.1` or `localhost`.
- **The estimate could read too short.** A run cut off by closing the app has an unknown length, so a Scan with such a run is no longer used to adjust the estimate.
- **Keyboard focus was lost** when a finished Scan updated the list. It now goes back to the same element or to the list's heading.
- **Two different steps with the same count were not announced** to screen readers. The AI checked that the new browser test fails on the old code.
- **Missing tests**: picking the right earlier Scan for the estimate, and the Scans page of the real app as `liquidoracle run` builds it.
- **Two wordings that were only in the code**, "Waiting to start" and the heading "Your Scans", are now in EXPERIENCE.md and epics.md too.

**Rejected, for example:** a message after a refused start (the list already shows the running Scan, and a message would need new wording), and adjusting the estimate when the speed setting changes (the default is already the fastest allowed).
