## 3. Bugs found in the AI's code

| Found by | Bug | Fix |
|---|---|---|
| The AI's own smoke test | On Windows, a second `liquidoracle run` bound the busy port without an error and said "running" while the first copy got every request | `run` checks whether the port answers before it starts, and stops with a plain sentence |
| Edge-case reviewer | The AI's `except OSError` around the server start could never run: Werkzeug catches the error itself, prints its own message and exits. The test for it faked an error that never happens | The dead branch and its test were removed |
| Blind reviewer | `${PORT}` in `.env` was filled in from the system's environment, against the rule the AI had just written | Interpolation turned off, plus a test |
| Edge-case reviewer | A `.env` that isn't UTF-8 crashed with a traceback | Now a plain error, plus a test |
| Edge-case reviewer | The architecture rule let `services` or `web` import `sqlite3` or `socket` | Network and database modules are now allowed only in `data` |
| Test-gap reviewer | Some tests could not fail: `--offline`/`--seed` were never sent through the real command, `port_in_use` itself never ran, and the online placeholder only asserted `True` | Real tests added |

The rule tests were also checked by planting real violations: `import requests` in `core`, `os.environ` in `web`, and turning socket blocking off. Each one made the suite fail.

In all, the three reviewers raised 26 findings. 17 were fixed. 2 were false: a `.env` with a byte-order mark works fine, and the `--mock-llm` flag belongs to stage 3. 7 were rejected with a reason, for example "the first slow test comes in Story 1.4". Every verdict and its evidence is in the spec's Review Triage Log.
