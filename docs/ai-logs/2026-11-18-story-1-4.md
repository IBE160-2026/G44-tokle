## 3. Bugs found in the AI's code

The AI found two in its own tests before the review:
- The first Sliver test used one winning and one losing Sliver, so the money it checked added up to $0 and proved nothing. Both now win, and the test also checks that leaving them out changes the result.
- A helper named `tested()` was picked up by pytest as a test. It was renamed.

The three reviewers raised 21 findings. The test-gap reviewer planted each suspected bug in a copy of the code and ran the tests, and five of them passed when they should have failed:

| Found by | Bug | Fix |
|---|---|---|
| Test-gap and blind reviewers | The test for "the other side of a Market wins at its own price" held only one side, so the code for the other side never ran. Writing `draws > price` instead of `draws > 1 − price` passed every test | A Market held on both sides at 60¢ and 30¢; each side must win at its own price. A golden count pins the side rule |
| Edge-case reviewer | A replay total sitting exactly on a bar edge could be counted in the bar below: `floor(0.3 / 0.1)` is 2 in floating point | Totals are now sorted against the stored bar edges themselves |
| Edge-case and blind reviewers | For tiny Wallets the bar width could be 2.5 cents, so the bars came out unequal once rounded to cents. A value exactly on the axis edge landed in the end bar | Whole-cent widths only; the last bar on the axis holds its top edge |
| Test-gap reviewer | No test checked the bars with fees, or that the axis isn't far too wide (a width 10× too big passed) | Two new tests, plus a table of bar widths |
| All three reviewers | The public function never got bad input in a test, and a Market with three outcomes was refused at 30 bets but accepted at 29 | All checks in one place, tested through both functions; fees that aren't numbers are refused too |
| All three reviewers | The ban on hidden randomness missed `from numpy import random` and `import numpy.random` | Caught now, with eight planted forms tested |

While fixing these, one of the AI's new tests failed on a replay total of exactly $2.00. The code was right (that value belongs on the axis), and the test was corrected.

In total: 13 fixed, 7 rejected with reasons (for example, "the chart marker uses the exact Real PnL by design: Edvard's 'two sums' decision of 5 November"), and 1 deferred. A negative Own Fee is still accepted, because refusing it could crash a real lookup over a rounding gap; the fee check in Story 2.2 is the place for it. The full table is in the spec's Review Triage Log.
