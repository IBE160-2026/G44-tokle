## 3. The build

A fresh implementation helper built it from the spec alone:
- `tests/browser/pages.py` (new): the shared page helpers, moved out of `test_pages.py`.
- `tests/browser/conftest.py`: a live app per test with the real job queue and worker, in front of a stand-in Polymarket the test can hold back, release or make fail. It never touches the network.
- `tests/browser/test_chart_script.py` (new): the slider keys, the tooltip (300 ms stay, Esc, never over the marker at 1280, 600 and 360 px), the marker's highlight, the build-up, the chart without the script.
- `tests/browser/test_progress_script.py` (new): polling, the swap, focus on the new heading, the copy button on the swapped-in Verdict, the "Polymarket did not answer" and "No Polymarket history found" pages, giving up after 30 failed polls.
- `tests/browser/test_pages.py`: forced-colours tests for the copy, theme and main buttons and the chart bars.
- `README.md`: what the browser tests cover and how to run only them.

**Proof the tests catch something:** the helper broke the scripts and stylesheet on purpose, one break at a time (23 breaks, then 8 more after the review), and every break made its test fail. One test missed a break at first (the build-up running twice) and was fixed.

**Found while building:** Chrome draws its own high-contrast border on a hovered or focused button, so checking the colour alone could not catch a missing rule; the test also checks that the app's own rule applies.

## 4. Review

Three reviewer helpers read the diff and filed 23 findings in 17 groups: 9 fixed, 2 deferred, 6 rejected with a reason (all in the spec's triage log). The main fixes:
- **An overclaim:** the live-lookup test said it checked that the address bar changes to the result, but in that flow the address stays the same, so a broken `replaceState` would have passed. The wording now says what is really checked; a test of the case where the address does change is deferred.
- **Missing checks added:** the marker's 300 ms stay after the pointer leaves, moving the pointer onto the tooltip or the tail label, a click on a bar ending a pinned highlight, a 404 from the progress URL, and the failure count resetting after one good reply.
- **Two possible flakes:** the build-up test could scroll back before the browser noticed the chart had left view, and the 30-poll loop had a fixed step count. Both now wait for the real event or a time limit.
- **Smaller ones:** the stand-in now fails on every read, not just the first; the cleanup checks the worker stopped; tests check the test data's shape first; the README paragraph is split into a short list.
