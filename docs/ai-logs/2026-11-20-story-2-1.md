Choices the AI made itself, written in the spec and the memlog:

## 3. What the live check found

The spec planned one live smoke test. While building, the AI also checked how Gamma answers when Markets are looked up by id, using a small probe script (4 requests, read-only, kept out of the repository). Result: **without a `closed` parameter, Gamma returns only open Markets.** `closed=true` returns only resolved ones, and `closed=all` is refused. The spike scripts always sent `closed=true`, so they never noticed. Without the check, every resolved Market would have gone missing in Story 2.2. The client now asks for resolved Markets first, then asks again for any still missing as open (memlog entry).

## 4. Bugs found in the AI's code

The AI caught four of its own mistakes before the review:
- The online smoke test asked for 5 rows per page, so it walked several pages instead of reading only the first, as the story asks. Caught while writing the README line about it. It now reads one page.
- A test expected a 0 s gap between two requests after a past `Retry-After` date. It forgot that the rate limiter still spaces requests 0.2 s apart. The test was wrong, not the code.
- The two-thread test first timed requests at the transport. The fake clock moves while the other thread sleeps, so those times could be late. It now reads the slot the limiter actually granted.
- A long inline Python script in the shell broke on quoting. It was moved to a scratch file.

The three reviewers raised 44 findings. The AI checked each against the code:

| Found by | Bug | Fix |
|---|---|---|
| Verification reviewer | The two-thread limiter tests still passed with the lock removed (0 failures in 300 runs): a fake sleep never blocks, so the threads never overlapped | A new test checks that the limiter reads the clock and sleeps only while it holds its lock. The AI first tried to force a race on purpose; that did not work (the second thread still saw the first one's slot), so it changed approach |
| Verification and blind reviewers | The real network layer had no test that runs in CI | Tests with `requests` swapped out: timeouts, no redirects, header case, error mapping, one session per thread |
| All three reviewers | A reply row that was not an object, or a numeric time, escaped as a raw Python error instead of "Polymarket gave an unreadable answer" | Rows are checked first, and every parse error becomes the typed error |
| Edge-case reviewer | A broken connection mid-reply, and a timeout while reading the reply body, escaped raw or lost the mid-walk restart | Both are mapped: the body timeout counts as a timeout, anything else as a failed connection. The AI confirmed in `requests`' own source that a body timeout arrives as a connection error |
| Blind reviewer | The Gamma reader filled in missing fields (`closed`, the outcome lists) instead of refusing them, though these decide whether a Market is resolved | Those fields are now required |
| Blind and edge-case reviewers | Whether a page "timed out" depended only on its last try | A page restarts the walk only when every try timed out |
| Edge-case reviewer | A page that did not say whether more pages follow was taken as the last; NaN or Infinity in a reply was accepted | Both are refused as unreadable |
| Blind reviewer | AD-3's new sentence read as "every other 5xx is retried", which the code does not do | AD-3 reworded; the build's assumptions are listed in the memlog |

In total: 14 groups fixed, 1 deferred, the rest rejected with reasons. For example, "a 429 pauses only the thread that got it" was rejected because only the one worker thread fetches (AD-5).
