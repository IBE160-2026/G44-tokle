**"Below all" (open since Story 3.1).** When a Wallet does worse than every one of the 10,000 replays, the chart's label says "below all 10,000 Simulations". That label is hidden from screen readers, and the sentence under the chart then only says "more than half the time". The AI gave two options:
- (a) add "That is below all 10,000 replays." to the sentence in that case;
- (b) leave it and list it as a known gap.

The AI recommended (a). **Edvard chose (a).** The AI changed the plan before any code: `EXPERIENCE.md`, `epics.md` (UX-DR24 and Story 3.1), the UX memlog and the Epic 3 context.

**Spec size.** The spec came to about 2,100 tokens; the workflow aims for at most 1,600. The AI recommended keeping it whole, as earlier specs of that size had gone fine. **Edvard kept it whole.**

## 3. The build

A fresh helper built it from the spec alone:
- `tests/browser/test_checklist.py` (new): one test per checklist item, keyboard only, reading each element's role, name, state and reading order (Playwright's accessibility snapshot) and the text of the live regions. It also checks the Real Wallets links, and opens every page with JavaScript off, including the live fetching and error pages.
- `tests/test_web.py`: heading, label and error checks on all 14 pages the app renders.
- `tests/browser/conftest.py`: two more small test apps, one with no Sample Dataset loaded and one over the committed real Wallets.
- `core/phrases.py`, `services/chart.py`: the "below all" sentence, with tests in `test_phrases.py`, `test_chart.py` and `test_web.py`.
- `docs/accessibility-check.md`, `docs/stage-1-check.md` (new) and the README.

The helper broke each test on purpose once, for example by removing the hidden "Verdict: " or the focus ring, and each test failed. No other app code needed a fix.

**One finding went to Edvard.** On the Lookup page the cursor starts in the address field (planned, UX-DR16), so the first Tab goes to "Check wallet", not "Skip to content" as checklist item 1 says. The helper did not change the page and reported it. The AI gave the reasons to keep the autofocus:
- the cursor already starts where the skip link would take you;
- item 2 relies on it, because after an empty submit the cursor lands back in the field.

The other option, removing the autofocus, would have changed the UX plan. The AI recommended keeping it. **Edvard kept it.** Checklist item 1 in `epics.md`, the spec's checklist table and the UX memlog now say that on the Lookup page the skip link is reached by Shift+Tab.

## 4. Review

Three reviewer helpers read the diff and filed 23 findings, all of them listed in the spec's triage log. The claims reviewer found no gap. Of the rest, 10 groups were fixed and 5 were rejected with a reason. The main fixes:
- **A test that proved less than it said.** The keyboard walk (item 11) quietly skipped any focus stop it could not identify. It now fails on any unexpected stop and names it. Making it stricter showed that Chrome wraps differently in each direction: Tab leaves the page once after the last control, while Shift+Tab goes straight from the first control to the last. The document says so.
- **The Real Wallets test** checked that at least 2 links existed. It now checks all 10, and that each name read out matches the text shown.
- **Overclaims:** the README said the app works "by keyboard and screen reader", though no screen reader runs; it now says what the tests check. The pending CI run on three systems got its own open item.
- **Smaller ones:** a polling loop with no pause, an error check that depended on one exact attribute order, a redundant condition, and gaps in the "cannot prove" list (text spacing, non-text contrast, orientation).

Rejected, among others: using "Simulations" instead of "replays" in the new sentence. The plan's word rule says on-screen text uses "replay", and only the marker label keeps "Simulations".
