# AI session log, 2026-11-20: Story 2.2, a Wallet's bets as one complete snapshot

- **Tool**: Claude Code (model Claude Opus 5.5) in the VS Code extension, using the `bmad-build` skill.
- **Student**: Edvard Tokle (G44).
- **What this covers**: Story 2.2, the second story of Epic 2. It was built on branch `story-2-2-one-complete-snapshot`, made from `main` after PR #24 (Story 2.1) was merged. The session ran past midnight into 21 November.
- **Result**: a lookup no longer reads a Wallet's whole history. `data/window.py` has the one window function, `positions_near`. It reads the latest 2,000 Positions in resolved Markets, gets each Market's resolution time, fee schedule, start date and tags from Gamma, and then reads only the activity those Positions need, up to a cap of 150,000 rows. Positions the capped read did not reach are left out as "not fully read" and counted. The window is saved as one snapshot that readers see only when it is complete, with one fetch per Wallet at a time. Offline Mode runs the same code through `OfflineClient`. 45 new tests, 695 in total, plus the online smoke test run by hand. The story stays in `review` until Edvard's pull request.

Choices the AI made itself, written in the spec and the memlog:
- `positions_near` is one function over any client's three raw reads, not a method on each client, so live and offline cannot drift apart (AD-13).
- If the 2,000th place falls inside a Market, that whole Market is left out, so the window never splits a Market (AD-20 couples its sides) and never goes over 2,000.
- A Market Gamma calls closed with a resolution time is in the window even when the result is unclear; the builder then leaves it out with that reason (AD-7, AD-11).
- A positions list that cannot be read whole gives "Polymarket did not answer", and no snapshot is written; the old one stays.
- A token on both lists counts once, from the OPEN list.
- The activity read starts at the earliest Gamma start date or first buy, whichever is earlier, so a missing start date cannot drop a buy.
- A Cut-off Date side is not built yet; that is Story 4.1.

## 4. Bugs found in the AI's code

The AI caught some of its own mistakes before the review:
- A test assumed 0x091596's two Gamma-unknown Markets would be logged as missing. They are only in the activity rows, so the window never asks Gamma about them, which is correct (AD-10). The test was wrong, not the code; it was split into two honest tests.
- Before the review, the AI broke the code on purpose in four places: no stop rule, a split Market, no Market cache, no Wallet lock. Each made a test fail.
- Long inline Python scripts in the shell broke on quoting twice, as noted in the handoff. They were moved to scratch files or done with the edit tool.

The three reviewers raised 27 findings. The AI checked each against the code:

| Found by | Bug | Fix |
|---|---|---|
| Edge-case reviewer | If Gamma kept timing out while the CLOSED walk checked its stop rule, the client took it for a positions page timeout and restarted the walk. Those Markets were already marked as asked, so their Positions would silently drop out of the window | A Gamma timeout there is now "Polymarket did not answer", and Markets count as asked only once Gamma has answered. The new test fails on the old code |
| All three reviewers | The cap can cut in the middle of one second. A Market resolved in exactly that second could keep half its fills and still count as fully read | That second now counts as not fully read too. AD-7 and the memlog were changed first |
| Verification reviewer | A capped read never went through the real fetch path in any test. Dropping the line that saves where the read stopped passed every test | Test through `fetch_wallet` with a cap of 10 (the same change now fails) |
| Verification reviewer | No test opened a database from Epic 1 (schema version 1) | Test: an Epic 1 database is rebuilt and takes a new snapshot |
| Verification and blind reviewers | The offline client's paging, sorting and cap were never run. When the AI checked its own new test, "offline ignores the stop rule" still passed | Direct tests of the offline client's pages and cap, and a cap below 1 is refused as the live client does |
| Blind reviewer | Several tests could pass without checking their claim (an empty window, lengths only, one fixture section) | Each now compares exact values |

In total: 10 groups fixed, 2 deferred, the rest rejected with reasons. For example, "unclear Markets take window places" was rejected because AD-7 and AD-11 make that choice on purpose. "One Market alone over 2,000 Positions gives an empty window" was rejected because a tested Market has at most two outcomes. Deferred to Story 2.6: a real Wallet whose capture stopped at the cap could read as complete offline. The full table is in the spec's Review Triage Log.
