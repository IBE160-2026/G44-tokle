## 3. ChatGPT round 1: four HTML layouts

On the student's request, the AI wrote a self-contained prompt for ChatGPT (`.working/chatgpt-prototype-prompt.md`): our exact colours, wording rules and content, with the versions to differ only in layout. The student ran it and got four HTML files (A classic report, B dense dashboard, C document style, D editorial rail), plus ChatGPT's own notes. ChatGPT recommended A.

The AI reviewed all four against the spines. Its recommendation was A, with B's Scans layout. It found problems shared by all four:
- the Verdict text was 13 px, and the heading "Verdict" was bigger than the Verdict itself;
- the odds phrase was plain body text;
- labels and notes were 10 to 11 px;
- the progress bar was grey;
- the chart would be read twice by screen readers.

It also found two problems in single versions: B's chart labels shrink to about 7 px, and D's tables scroll sideways on a normal laptop.

All four files are kept unchanged in `imports/round-1-html/` as a record.

The student confirmed position A, the address and date in the tab titles, and showing progress only in the Scans tab. His reaction to the progress ring: he liked it.

### Interaction: hover, focus and the chart

The student asked for the page to feel satisfying to use:

> "subtle hover effects on everything clickable, like the top bar links highlighting, buttons lifting a tiny bit, table rows lighting up, the copy button giving a little "copied" feedback. same look when u tab to it with the keyboard. only clickable stuff should react tho. n make the luck chart animate in, the bars building up into the curve n then the wallet marker dropping in. also on the chart: hovering a bar shows a small label with its range n how many replays landed there, n hovering the wallet marker highlights all the bars to the right of it with a label like "2,500 of 10,000 replays did this well or better", so u can actually see the 1 in 4. make it work with the keyboard too. keep it all quick n calm, n turn it off for people with reduced motion on."

What the AI did:
- **Spec first.** It wrote the rules into DESIGN.md (an "Interaction states" table, timings, the lift shadow) and EXPERIENCE.md (chart explore, wallet marker, build-up, reduced motion), then rebuilt the Verdict mockup to match.
- **Keyboard design (the AI's choice).** The bars are one *slider*: arrow keys step bar by bar, and a screen reader reads "$30,000 to $35,000: 289 replays". The wallet marker is a button; focus highlights the tail, Enter or a click pins it (this also works on touch screens), and Esc clears it.
- **Honest numbers (the AI's catch).** The bars from the wallet's bar rightwards add up to 2,508, not 2,500, because the wallet's bar is only partly above $40,180. The label uses the exact 2,500 from the p-value, and the spec says why. The bar counts are whole numbers that add up to exactly 10,000.
- **Tested in a real browser.** It drove the page with Playwright on the installed Chrome, by mouse, keyboard and reduced motion. All checks passed with no console errors: the chart builds on view, hover labels show, Tab reaches the marker and its message is announced, Esc clears, reduced motion shows the chart complete, and the theme pick survives a reload.
- **Fixed after the test.** Two focus rings crossed the "This wallet" label, so they were moved; the highlighted bar was softened from pure black.

## 6. Errors found in AI output, and how

| Where | Error | How it was found | Fix |
|---|---|---|---|
| ChatGPT image (and the AI's own prompt) | The luck chart was statistically wrong. With no edge, each bet is replayed at its own price, so the replays average exactly $0 and the bell must be centred on $0. With odds "1 in 4", a quarter of the replays must lie beyond the wallet's marker. The image centres the bell near +$5k and puts $40,180 far out in the tail, which fits roughly 1 in 50 to 1 in 100. The AI's prompt had already given an axis range (−$60k to +$80k) that did not fit the odds | The AI checked the picture against the PRD's definitions (§3 Simulation, p-value) | The mockup's chart is a bell centred on $0, spread so exactly 25% of the 10,000 replays lie at or beyond $40,180. The "About this chart" text says luck alone averages $0 |
| ChatGPT round-1 HTML | The five shared problems in §3, plus B's tiny chart labels and D's sideways scroll | The AI read the code against DESIGN.md and EXPERIENCE.md | Not fixed in those files; the spines now require the opposite, and the mockup follows the spines |
| The AI's own image compression | Squeezing the images to 256 colours turned the blue accent dark and the warning stripe brown, which are the colours that matter most in a style reference | The AI looked at the result before moving on | Redone from the originals as WebP, which keeps every colour |
| The AI's own logo, first two tries | The cut through the bell split it into two pieces that read like "dl"; the ring was too heavy next to the reference | Screenshots of the SVG at 16, 24, 32, 64 and 160 px beside the reference | Full-height marker with a thin gap on each side, a bigger bell, a thinner ring; three marker positions offered to the student |
| The AI's own interactive chart, first build | The keyboard focus rings of the bar slider and the marker button crossed the "This wallet: $40,180" label; the highlighted bar in pure black looked harsh | Playwright screenshots of each state (hover, keyboard, marker) | Slider and button areas start below the label; the highlight is 80% ink |
| The AI's own spec and mockup (found by the reviewers) | Among others: one component under five names; three PRD-required elements placed differently in different sections; the luck-chart marker's message read twice by screen readers, and hover labels that vanished when pointed at; a silent copy failure; "what the wallet really made" (Real PnL leaves out Exit PnL); a rank column that suggests "best wallet" | The three review subagents, reading the files against the PRD and WCAG, and driving the page in Chrome | Fixed in both files and the mockups (§5) |
| The AI's own test script | The Playwright stub for a refused copy ran the fake function instead of installing it, so the test crashed | The test error | The test was fixed, not the page |
| The AI's own mockup, first build | The Verdict wrapped onto two lines; the y-axis title touched "400"; the x-axis labels overlapped on phones; numbers outside tables were monospace, against DESIGN.md | Screenshots in headless Chrome at 1440 px (light and dark), 390 px and 320 px | Wider content column, more spacing, short axis labels ("−$100k") under 640 px with the end labels hidden under 400 px, sans-serif numbers outside tables |

## 7. What we learned (the student's words)

> "chatgpt's html came out flat, image references gave us the taste, n claude turns them into code"

The four HTML layouts were correct in content but flat: small type, no hierarchy, everything the same weight. The images had the hierarchy and character that the HTML lacked. The useful split was ChatGPT for the picture, the spines for the rules, and Claude for code built to those rules. That keeps the code clean and makes the rules checkable.
